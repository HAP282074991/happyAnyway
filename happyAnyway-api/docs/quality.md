# 后端验证能力

| 检查 | 覆盖 | 边界 |
|---|---|---|
| Maven verify | 编译、打包、基础行为和 ArchUnit | 不证明业务正确或真实 MySQL 可用 |
| local 行为测试 | 健康、OpenAPI 描述、默认拒绝未知业务路由 | 不含业务登录与权限实现 |
| 架构规则 | 已实现的层级依赖约束 | 空业务层不证明未来所有模块约束 |
| 文档结构 | 必需文件与本地链接 | 不替代规范语义审查 |
| 根 CI | 调用统一检查、保留报告 | 远端运行及分支规则另行启用验证 |

真实 MySQL／Flyway 用例、发布契约兼容、业务会话与业务联调在相应阶段安排。架构若承诺某项基础能力，仍应验证或标记未验证。

Service 接口／Impl 配对与调用边界已接入 ArchUnit；现有 13 条规则有代表性正反样例。事务语义、跨模块依赖、日志脱敏等未被完整自动覆盖的规则按 [规则索引](index.md) 人工审核。

Service 识别覆盖整个生产包，并验证错包、错名、缺注解及直接依赖实现的反例；合法接口注入和配置组装保持允许。业务层为空仍不代表未来所有模块约束均已覆盖。

profile 初始化器在容器刷新前拒绝 local/mysql 混用；测试覆盖两种排列顺序、单独 profile 校验及 Spring 启动注册。mysql 单独校验通过不代表真实数据库启动已验证。

这里只说明能力，不保存历史通过结论；每次实际结果写入根任务证据，架构验收后按生命周期清理筹备报告。
