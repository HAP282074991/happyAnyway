# 数据库规则

适用：MySQL、Entity、Mapper、SQL 和 Flyway。层级依赖以 [架构](../../ARCHITECTURE.md) 为准；事务用例组织见 [开发规则](development.md)。

## DB-01 建模与一致性
- 使用 InnoDB、utf8mb4；在建库或迁移中明确排序规则，对大小写敏感标识特别说明比较方式。
- 表和字段使用 snake_case，Entity 字段使用 lowerCamelCase，映射保持明确。
- 主键、非空、唯一约束及适用外键根据真实业务设计，不能只靠应用查询维持唯一性。
- 金额使用精确表示；明确时间语义并统一连接和应用时区。对外表达遵循 [接口规则](api.md)。
- JSON 字段用于确有动态结构的数据，不用它绕过关系和字段建模。
- 每张表单独决定删除/软删除、保留和唯一性策略；不机械给所有表加逻辑删除。
- 只有多租户需求明确后才设计租户隔离，不预建未经确定的业务能力。

## DB-02 Mapper 和 SQL
- 接口与 XML 的模块目录一致，namespace 与接口全限定名一致，statement id 与方法对应；重命名时一起更新。
- 值参数使用 MyBatis 参数绑定。动态列、表或排序不能直接拼接客户端输入，必须在后端映射到有限白名单。
- 使用明确列清单；分页和批量操作有边界，不能让外部参数触发无界全表返回。
- 修改操作核对影响行数；需要并发保护时使用合适的条件更新、锁或唯一约束，按业务验证。
- 不在 Mapper 中组织跨业务用例；SQL 与 Entity 调整同步评估响应 DTO 和契约。

## DB-03 索引与性能
- 索引根据过滤、关联和排序路径设计，写明关键查询依据；不为每个字段默认建索引。
- 关注 N+1、无条件更新、深分页和无界批量操作。
- 对已识别的高频或大数据查询使用执行计划和代表性数据验证，不凭空承诺性能。
- 引入缓存前先确认查询与索引问题；不能以缓存替代必要约束。

## DB-04 迁移
- SQL 放 src/main/resources/db/migration，使用 V<唯一版本>__<描述>.sql；在共享环境执行后保持不可变，以新迁移修正。
- 首次初始化和已有版本升级都必须考虑；开发种子数据与生产基础数据分离。
- 不随意开启 baseline、修改历史校验记录或删除迁移以掩盖环境差异；修复要说明原因和影响。
- 重要变更采用兼容扩展、数据回填、调用方迁移、最终清理的阶段方式。
- MySQL DDL 不能按普通业务事务假定全部可回滚；失败恢复必须考虑部分执行状态。
- 大表变更评估锁定、耗时和磁盘占用，不能直接把本地快速执行等同于生产安全。
- 应用回滚与数据库恢复分别设计。Flyway clean 在当前配置中禁用，不能为方便打开。

## DB-05 环境与数据操作
- 使用隔离开发/测试库，凭证通过环境提供，不写入仓库。
- 生产运行与结构迁移使用匹配职责的权限；运行账号不应长期持有不必要的 DDL 权限。
- 不自动复制本地业务数据到生产，不对未知环境执行清理或初始化。
- 涉及已有数据的变更先确认目标环境、选择条件和影响；操作授权取自当前任务，例行本地工作不额外制造审批。
- 备份应有可执行恢复验证；恢复目标和保留周期在部署需求明确后确定。

## DB-06 验证状态
