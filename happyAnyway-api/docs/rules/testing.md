# 测试规则

适用：测试代码、检查脚本和验证活动。预期来源于 [需求与验收](../product/acceptance.md)，架构正确性来源于 [架构](../../ARCHITECTURE.md)，不能只照抄当前实现。
状态：以下包括未来用例的要求；当前用例数量和已接入工具见 [质量状态](../quality.md)。

## TEST-01 按风险选择验证
| 改动 | 必需的适用验证 |
|---|---|
| 文档、导航 | 文档结构脚本，核对权威来源与实现 |
| Service 业务逻辑 | 正常、边界、拒绝和失败恢复场景 |
| Controller / DTO | 绑定、参数校验、状态码、响应字段及权限 |
| Mapper / SQL | 真实 MySQL 查询、映射、约束和影响行数 |
| 表结构迁移 | 空库初始化；已有支持版本的数据升级路径 |
| API 契约 | 输出与约定一致；破坏性差异及兼容安排 |
| 配置、认证 | 对应 profile 启动、默认拒绝及公开范围 |
| 架构规则或检查脚本 | 合法样例通过、代表性违规样例失败 |
| 构建、依赖 | mvn verify；涉及运行时行为时做启动验证 |

只运行与改动相关的检查；业务代码、构建及架构测试改动通常执行 mvn verify。纯文档改动不要求重跑全部 Java 测试。

## TEST-02 测试层次与发现
- 单元测试验证可观察的业务结果，能不用 Spring 时不启动完整容器。
- HTTP 测试覆盖真实绑定、校验和安全链；模拟身份用于限定场景，不能代替真实认证链的专门测试。
- 数据库测试使用与生产同系列的 MySQL，不能用 H2 或 Mock Mapper 证明 SQL 和事务正确。
- 当前 Maven 配置运行 *Test；若采用 *IT 命名，必须同步接入 Failsafe 并证明 verify 会执行它们，不能只创建未被发现的测试文件。
- 不以测试数量或统一覆盖率代替质量；为具体风险编写测试，不机械覆盖 getter/setter。

## TEST-03 模拟、数据与隔离
- 可在 Service 单元测试中模拟 Mapper，但数据库行为必须另有集成验证。
- 外部微信或第三方 API 使用可控替身，不在普通测试中产生真实扣费、发信或用户操作。
- 使用固定数据和可控制时钟，避免依赖顺序、当前时间、长 sleep 或公共数据库状态。
- Testcontainers 或明确隔离的测试库均可；清理只针对本次测试拥有的数据/环境。
- 不使用生产凭证、生产数据或共享开发库进行破坏性测试。
- 外层测试事务自动回滚不能证明 Service 自身事务正确；回滚、提交和并发场景应显式验证。

## TEST-04 边界与失败场景
- 根据业务覆盖空值、长度、非法枚举、分页上限、未登录、无权访问、资源不存在。
- 涉及幂等和并发时验证重复请求、竞争更新及不重复产生副作用。
- 涉及外部依赖时覆盖超时、错误响应和恢复失败，检查不会返回假成功。
- 新增安全配置时验证受保护路由仍被拒绝，不能通过全局 permitAll 让测试变绿。

## TEST-05 保护验证能力
- 不为了通过检查删除测试、随意改预期、增加无依据的 disabled/skip 或降低断言。
- 修改已有预期要说明需求或契约发生了什么变化。
- 修改架构规则时使用隔离样例验证拦截能力，违规样例放测试范围，不污染生产包。
- 空层允许匹配不是实际覆盖；建立业务类后检查命名、扫描范围和规则是否确实命中。
- 本轮不补写历史规则的全部反例测试，该缺口在质量状态中记录。

## TEST-06 结果与阻塞
- 记录命令、日期、退出结果、适用代码状态和未执行项；可以链接报告，不粘贴大量无关日志。
- 没有 Docker、数据库或凭证时标记未验证，不能把“跳过”记成通过。
- 历史测试结论只作为历史证据。验证后又修改相关代码，需要重验受影响部分。
- 修复一次已观察失败可重跑；没有新变更或疑点不反复全量测试。
- 验证结果交付格式见 [审查规则](review.md)，实际命令见 [运行说明](../runbooks/development.md)。
