# 接口规则

适用：Controller、DTO、认证与公开接口契约。本文定义后续业务接口的统一约定，当前业务接口尚未实现；Swagger 端点存在不代表契约发布流程已建立。

## API-01 路径与协议
- 业务 HTTP API 使用 /api/v1 前缀，路径以资源语义为主，HTTP 方法表达操作；健康检查和工具端点不强制套业务路径。
- GET 不执行业务写入。创建、修改、删除的成功状态按实际语义选择；不把所有失败封装成 HTTP 200。
- JSON 字段使用 lowerCamelCase。操作名称、必填条件和返回含义写入契约，不能仅靠前端猜测。

## API-02 DTO 与数据表达
- 每个操作按需求定义请求/响应 DTO，不接受 Entity 作为任意字段更新载体。
- 请求 DTO 只开放该操作可修改字段；资源所属用户不能直接信任客户端传值。
- 对外 ID 用字符串；时间点使用带时区的 ISO 8601。日期、时间点和持续时间分别表达，不混用。
- 金额明确单位和币种，使用最小单位整数或精确十进制表达，并在具体契约中固定，不使用浮点计算权威金额。
- 明确字段缺省、null、空字符串含义；更新操作尤其需要区分“不修改”和“清空”。
- 枚举使用稳定的公开值，不将 Java 枚举序号作为协议。
- 不返回密码散列、会话令牌摘要、内部数据库字段或异常堆栈。

## API-03 错误与分页
- 业务错误响应约定为 code、message、requestId；code 稳定可判定，message 可读且不含内部细节。
- 通常使用 400 表达参数错误、401 未认证、403 无权操作、404 不存在、409 状态冲突；实际接口需明确并测试。
- 未知异常返回通用服务端错误，保留服务端排查证据，不泄露 SQL 或连接信息。
- 默认列表契约采用 page/size，请求 page 从 1 开始，size 默认 20、上限 100；响应 items/page/size/total。大数据流可另定游标分页并说明原因。
- 排序字段使用白名单；同值排序增加稳定次序，不能把用户提供的排序字符串直接当 SQL。
- 本节为业务接口基线；当前 Spring Security 拒绝响应尚无统一 JSON/requestId，需在业务接口落地时补齐，不能声称已经实现。

## API-04 身份和权限
- 使用后端可信身份与内部用户 ID；跨端身份绑定不等于仅凭一个外部标识自动合并账号。
- 认证成功不等于有资源权限；Service 检查所有权、角色或其他业务限制。
- 不以 CORS、隐藏按钮或客户端校验作为授权手段。
- 新接口显式配置公开或受保护范围，不扩大成全局放行。
- 新的 Cookie、跨域、令牌方案需说明 CSRF、撤销、过期与客户端存储策略；不能为修复联调问题直接关闭相关保护。
- 具体会话方案尚未实现，不在本文假定已有登录能力。

## API-05 幂等、重试与版本
- 对重复请求会产生危险副作用的写操作定义幂等策略，明确键作用域、过期和同键不同参数处理。
- 客户端重试不能成为后端重复写入的理由；服务端以事务、唯一性等机制验证处理结果。
- 已发布字段改名、删除、类型变化、含义变化或新增必填条件视为潜在破坏性变更。
- 检查旧客户端兼容，必要时新增版本并提供迁移安排，不假设各端同时升级。
- 后端生成 OpenAPI 作为发布契约，版本、差异和客户端采用情况可追踪；不能要求前端直接跟随后端内部模型。
- 契约导出/差异工具尚未接入，现阶段修改需留人工差异说明，不能报告自动兼容检查通过。
