# 工作入口

本文件是初版 Harness 约束，后续讨论后逐步细化。

## 先阅读
- README.md：当前工程状态与运行入口。
- ARCHITECTURE.md：职责和依赖边界。
- docs/index.md：需求、决策、计划与验证文档。

## 工作约定
- 先理解需求与验收条件，再修改代码；业务未明确时不自行添加业务模块。
- 遵守本仓库架构，不引用其他前端仓库的代码。
- 小改动直接实施；跨模块或涉及数据/接口变化的任务记录执行计划。
- 不提交密钥、真实令牌、生产数据或本机私有配置。
- 修改行为、接口或操作命令时同步相关文档。
- 未实现的脚本、未执行的验证不得报告为通过。
- 不擅自发布生产、操作生产数据或扩展任务范围。

## 完成标准
- 满足本次明确的验收条件。
- 执行当前实际可用且与改动相关的检查。
- 报告变更、验证结果及未验证项。
- 复杂任务更新计划、决策与已知缺口。

## 当前检查
- 当前可运行：npm run verify（lint、类型检查、编译、文档与资源检查）。
- 开发：npm run dev，随后在微信开发者工具导入本仓库。
- 修改 TypeScript，不编辑生成的 JavaScript。检查不代替开发者工具和真机验收。

## 共享规格入口
- 产品需求、功能划分和跨端验收以同级 happyAnyway-specs 为权威来源；先读取本仓库 specs-reference.json。
- repositoryPath 相对本仓库根目录解析；按引用版本读取规格，不套用其他实现仓库的开发规则。
- 当前 bootstrap-unpinned 仅用于初始化与讨论；正式功能开发前建立明确规格提交。规格不可访问时报告，不猜测业务。
- 新工作区：D:\AIProject\happyAnyway；只在本仓库授权范围内实施。
