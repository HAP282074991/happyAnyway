# 微信工程入口

职责与读写权限遵循根 docs/agents/ 中对应岗位配置，公共协作遵循[部门流程](../docs/workflow.md)；[根 AGENTS.md](../AGENTS.md)仅配置项目经理，不授予执行岗位权限。本文件供微信开发、审核和测试按任务读取，只维护微信工程要求。

## 接手

- [项目说明](README.md)、[架构](ARCHITECTURE.md)、[文档索引](docs/index.md)、[质量与交接状态](docs/quality.md)。
- [规格引用](specs-reference.json)指定采用的根需求版本；解析规则见[需求入口](../docs/requirements/README.md)。

## 实现

按任务读取以下专项规则；跨多个范围时合并阅读：

| 工作 | 规则 |
|---|---|
| 页面、组件、客户端流程、接口使用和依赖 | [开发规则](docs/rules/development.md) |
| 自检、测试代码、联调与平台验证 | [测试规则](docs/rules/testing.md) |
| 独立审核、整改复审与交付核对 | [审查规则](docs/rules/review.md) |

- 修改 TypeScript、WXML、WXSS，不编辑编译生成的 JavaScript。
- 遵守本工程架构，不引用其他前端工程的实现代码。
- 小改动直接实施；跨模块、数据或接口变更按[计划约定](docs/exec-plans/README.md)记录。
- 平台能力、权限与交互异常以需求为依据，业务未明确时不添加占位业务。

## 审核与测试

- 审核需求符合度、架构边界、页面状态、接口使用和错误处理；整改交开发，修复后复审。
- 测试按需求验收条件覆盖主流程、异常和适用平台场景；跨端测试必须注明真实接口或模拟数据。
- `npm run verify` 执行边界回归、lint、类型检查、编译、资源与文档检查，不代替开发者工具和真机验收。
- 缺少 AppID、设备或环境时明确未验证，不将跳过记为通过；开发自检和独立测试分别记录。

## 运行与交接

在本工程目录执行 `npm run dev` 后导入微信开发者工具，完整步骤见[运行说明](docs/runbooks/development.md)。
交付更新质量与交接状态，项目经理汇总根进度；不复制公共需求和管理规则。
