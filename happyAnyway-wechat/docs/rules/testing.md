# 微信测试规则

规则版本：WX-TEST-V1-20260915。

适用：获派的微信工程自检、测试代码和独立验证。预期来自任务指定的根需求、交互和验收条件；工程基础验收见[验收说明](../product/acceptance.md)，架构约束见[架构](../../ARCHITECTURE.md)。不以当前实现倒推预期。

## WX-TEST-01 按改动选择验证

| 改动 | 必需的适用验证 |
|---|---|
| 纯文档与导航 | 本地链接检查、核对引用和实际能力；无实现变化不要求重复完整构建 |
| TypeScript、工具函数、客户端流程 | 类型检查、编译；适用的正常、边界和失败用例 |
| 页面与组件 | 已确认交互、加载/空/失败状态、事件与导航、重复操作、退出和重新进入 |
| 异步请求、搜索、刷新、分页 | 超时与失败、重复提交、响应乱序、退出后回调、分页重试与去重 |
| 接口适配 | 参数、字段、状态码、业务错误及契约版本；实际接口联调单独记录 |
| 登录、会话、存储、授权 | 适用的未登录、失效、拒绝、取消、存储失败、缓存过期及用户切换 |
| WXML、WXSS、页面配置 | 开发者工具编译与实际交互；适用屏幕、长文本和键盘场景 |
| 网络边界或静态检查规则 | 合法样例通过，已知等价违规写法失败，规则确实由验证入口执行 |
| 构建、依赖、平台能力 | npm run verify；开发者工具与受影响真机场景，注明环境 |

业务尚未实现的场景不要求提前创建业务代码；本表在对应获派改动出现时执行。

## WX-TEST-02 本地检查与测试发现

- 在微信工程目录执行 npm run verify，运行现有边界回归、ESLint、类型检查、编译、资源和文档检查；各命令用途见[质量状态](../quality.md)。
- 纯文档可运行 node ../scripts/check-docs.mjs --markdown-tree .；涉及工程实现、依赖或构建时执行完整验证入口。
- 当前 Node 测试入口运行 tests/*.test.mjs；新增测试应证明会被入口发现。采用其他目录、TypeScript 测试或其他工具时，同步接入获派验证入口并报告实际执行结果。
- 断言可观察结果和拒绝行为，不只检查函数被调用；合法与非法样例成对验证边界，避免用测试数量代替覆盖质量。
- 不删除有效测试、降低断言、忽略错误或把失败改成跳过来获得绿灯。

## WX-TEST-03 隔离与异步用例

- 外部微信能力和网络调用在普通自动测试中使用可控替身，明确替身范围；不产生真实发送消息、付款等用户操作。
- 并发与时间相关测试使用可控响应顺序和时钟，避免依赖公共服务、当前时间或长时间 sleep。
- 验证错误后的页面状态、重试机会和资源清理，不能只断言成功请求返回值。
- 真实联调使用获准环境及隔离数据，注明地址环境和契约版本；不提交真实令牌、生产数据或本机私有配置。
- 测试代码不能通过模拟掉待验证的判断或边界，冒充其真实执行结果。

## WX-TEST-04 开发者工具、真机与证据边界

- 本地 lint、编译、资源存在检查不证明页面可用、微信 API 可用或真机交互正确。
- 页面或平台能力改动按适用范围验证开发者工具和真机；记录工具/基础库版本、设备系统、使用的 AppID 类型及实际操作结果。
- 明确真实接口、模拟接口和未接入状态；模拟通过不等于契约联调通过，游客环境不能替代受账号条件限制的验证。
- 缺设备、AppID、后端或其他环境时逐项标记未验证，说明影响和补验条件；不能将未执行写为通过。
- 发布行为另需授权；验证任务不自动授予上传、提交审核或发布权限。

## WX-TEST-05 缺陷、复测与交付

- 缺陷提供被测版本、环境、前置条件、操作步骤、预期与实际、影响及必要证据；不将敏感信息写入报告。
- 开发完成修复后复测原失败路径及受影响路径；实现变化后，旧版本通过结果不能直接沿用。
- 报告记录实际命令、时间、结果、场景和未验证项。独立测试与开发自检分别记录，不能把自己实现的业务作为独立测试结论。
- 测试岗位按派工输出报告并反馈项目经理，遵循[部门流程](../../../docs/workflow.md)；不越权修改需求、业务实现或自行判定用户验收。
