# 微信开发规则

规则版本：WX-DEV-V1-20260915。

适用：获派的 TypeScript、WXML、WXSS、页面配置及客户端依赖变更。职责与写入权限仍以岗位配置和派工为准；目录职责以[架构](../../ARCHITECTURE.md)为准，操作步骤见[运行说明](../runbooks/development.md)。

本文件规定后续实现要求，不代表相关业务或基础封装已存在；自动检查范围见[质量状态](../quality.md)。

## WX-DEV-01 开发前与范围

- 核对任务、已确认需求、交互、验收条件、接口契约和工程规格引用；影响业务正确性的未知项交产品设计澄清，不能自行补造业务规则。
- 核对实际 Git 状态和待改文件，保留他人已有修改；跨模块、数据或接口变更按[执行计划](../exec-plans/README.md)留记录。
- architecture 阶段只做获派架构工作，不为占位目录填入用户、订单、登录等未确认业务。
- 只修改源文件，不手改编译生成的 JavaScript 或 source map；生成方式沿用现有 TypeScript 工程。

## WX-DEV-02 目录、命名与类型

- 页面和组件负责展示、交互和生命周期；services 组织本端操作流程，api 负责接口类型与错误映射，platform 封装微信能力。会话状态放 state，通用纯函数放 utils。
- 页面不承载重复的请求组装或跨页面流程；不得把 utils、全局对象或动态调用变成绕过既有边界的入口。
- 命名说明职责与业务含义，同一业务的类型、文件和接口名称保持一致；不为形式统一添加无实际复用的基类或通用框架。
- 使用明确的输入、返回值和数据类型；未知外部数据先校验再收窄，不用 any、忽略类型错误或无依据的类型断言掩盖契约问题。
- 展示数据与接口原始数据按需要区分，不把整个响应、请求句柄、定时器或敏感信息放入页面可渲染状态。

## WX-DEV-03 页面状态与生命周期

- 按需求明确加载、成功、空数据、失败及适用的权限受限状态；加载结束和失败路径都能恢复可操作状态，不用空列表伪装请求成功。
- 页面间传参和事件输入按外部输入校验；导航目标和必需参数与交互方案一致。
- 连续搜索、刷新、分页等并发请求要处理过期响应，避免旧结果覆盖新状态；分页失败或重试不得重复追加、跳过或串用另一查询的数据。
- 防止重复提交；按钮禁用或客户端去重不能替代服务端的权限、状态校验和幂等保障。
- 页面或组件退出时清理本任务创建的定时器、监听等资源；异步完成后先确认结果仍属于当前有效页面/请求，再更新界面。
- 页面状态通过框架支持的更新方式同步；只提交界面需要的变化，避免频繁传递大对象。长列表或高频更新出现时，按实际场景验证，不预设无依据的性能指标。
- WXML、WXSS 与已确认设计一致；适用的不同屏幕、长文本、键盘遮挡及交互反馈纳入验证，不自行改变产品方案。

## WX-DEV-04 接口与平台能力

- platform 之外不得直接引用 wx.request，包括计算属性、别名等绕过写法；业务调用经 services/api 使用统一传输边界。仅在获派请求业务时实现所需封装。
- 请求参数、响应字段、状态码和业务错误遵循锁定契约；不能只凭网络回调成功就认定业务成功。
- 明确超时、断网、业务拒绝及适用的会话失效处理；用户提示与诊断信息分开，不将内部错误原样展示。
- 重试必须有界，并确认操作是否可安全重复；非幂等写操作不能因超时自动重复发送。
- 登录、存储、授权等微信能力通过 platform 封装；权限拒绝、取消、不可用等分支按需求处理，不假定调用总会成功。
- 真实接口与模拟数据明确标识，模拟模式不得静默接管失败请求或冒充真实联调；契约升级后核对受影响调用方。

## WX-DEV-05 权限、存储与环境

- 客户端展示和按钮限制不能替代服务端权限、金额或其他权威业务判断。
- 服务端密钥和私钥不得进入客户端；会话凭据只按已确认方案处理，不放入 URL、渲染数据或日志，不将客户端存储视为可信授权依据。
- 仅保存需求所需数据，说明缓存有效期、失效和适用的登出清理；存储失败或旧格式数据需有明确处理，避免不同用户间串用缓存。
- 开发、联调地址与配置须明确；不默认关闭域名等校验，不把本机可用当成真机可用。
- 实际 AppID、基础库和设备验证依照获派环境记录；缺失时标记未验证，不将游客环境测试视为完整账号能力验收。

## WX-DEV-06 日志、注释与错误处理

- 关键请求失败、状态变化和不可恢复错误要可定位；日志包含操作及必要的非敏感上下文，不输出令牌、完整请求响应或个人敏感数据。
- 不吞掉 Promise 拒绝，不写空 catch，不通过清空数据掩盖错误；在负责处理的边界记录原因，避免各层重复输出同一错误。
- 新增或修改的模块、导出类型及公共函数用简洁中文注释说明职责；接口方法说明输入、返回值、错误及必要限制，字段说明单位、可空性等不显然的信息。
- 生命周期资源清理、并发控制和兼容逻辑说明原因；注释与实现同步，不逐行翻译代码，不保留大段废弃实现。

## WX-DEV-07 依赖与交付

- 新依赖说明用途、兼容范围和维护影响，依赖与锁文件同步；不进行无关升级，不因后端规则而强行引入前端框架。
- 修改构建、打包或依赖时核对生成资源与实际运行方式，不能只凭类型检查通过判断运行可用。
- 按[测试规则](testing.md)验证，按[审查规则](review.md)交付；同步必要文档、配置示例和契约引用，单独列出未验证项。
