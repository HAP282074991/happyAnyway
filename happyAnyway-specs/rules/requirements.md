# 需求分析与功能划分
1. 明确用户、使用场景、要解决的问题、目标与约束，区分用户事实、分析假设和建议。
2. 划定本期范围和明确不做的内容；影响业务正确性的未知条件列出待确认，不自行补成决定。
3. 按业务能力划分功能，每项功能有职责、输入输出、依赖和边界；Controller/Service 不是功能划分。
4. 描述主流程、异常、角色权限、数据所有权、状态转换；按实际需要补并发、幂等、离线等场景。
5. 写可观察的验收条件，分别标明后端、客户端和联调责任。
6. 拆解为可验证交付项，标明前置依赖、接口、范围、验收和规格版本。
7. 记录跨端差异，例如微信特有授权；共同业务规则不因某端实现方便而改变。
8. 尚无具体业务，不能将示例收藏或订单登记为已批准功能。
