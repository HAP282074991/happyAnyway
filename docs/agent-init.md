# 长期岗位 Agent：创建与接手

本文件是岗位创建、替换与接手的统一登记入口，和其他项目文档一起保存在根 docs/，不能只依赖聊天记忆。

## 新 Agent 从这里了解项目

1. [根规则](../AGENTS.md)：项目结构、公共权限与工程导航。
2. [部门流程](workflow.md)：跨岗位流转、交接与返工；从岗位配置入口读取自己的职责文件。
3. [项目进度](progress.md)：当前目标、成果、阻塞和验证证据；项目经理职责直接见[根 AGENTS.md](../AGENTS.md)。
4. 本文件的岗位登记及创建记录：确认自己为何创建、接替谁、采用哪些职责和限制，再读取相关工程入口。

根 Agent 已是项目经理，不在本招聘流程另行创建；docs/agents/ 只配置待招聘的五个岗位。目录存代码和文档，招聘岗位用长期独立任务承载。项目经理统一调配，当前先完成 Harness 并验收，再开发业务。

## 创建方式：逐个确认，逐个创建

- 用户已决定不批量创建。建议顺序为产品设计、后端开发、微信开发、审核、测试；用户可调整顺序。
- 用户说“初始化 agent”或提出创建某岗位时，先查看下方登记及现有任务，只处理当前岗位。仅讨论或修改说明不触发创建。
- 与用户明确五项：职责、决策与读写边界、接单输入、交付标准、协作及反馈关系。通用约定引用部门流程，个别岗位的补充经确认后写回 docs/agents/ 对应配置，避免两份规则。
- 记录本岗位职责与边界的确认依据；用户确认并授权创建后再执行。已有明确授权不重复询问；总体部门模式已通过不等于每个岗位的具体边界已确认。
- 查询项目和现有任务，匹配角色、项目与范围后复用，否则创建一个长期独立任务；遵循工具的环境要求，不以临时子 Agent 替代。
- 创建消息引用对应岗位配置的实际路径及版本，写清实际工作路径、可写范围、当前进度及规则入口，要求 Agent 读取并遵循。仅要求阅读并简短确认，等待后续派工，不自动盘点、开发、审核、测试或发布。
- 收到创建结果和接手确认后更新本文件，再向用户报告。排队记为待就绪，失败如实记录，重试前检查以免重复；不自动创建下一个岗位。

## 每次实际创建或复用后记录

在本文件末尾按日期追加一次记录，并更新上表当前任务。只为实际事件记录，不预建空档案。

- 岗位、日期、创建／复用／替换原因，以及用户确认该岗位职责和创建授权的依据。
- 实际任务标题、正式任务 ID、项目标识、运行位置与负责目录；排队阶段的临时标识单列，不冒充正式 ID。
- 当次采用的岗位配置路径及版本（未提交须说明），已确认的特殊边界与当前任务范围。
- 完整保留实际发送的创建／接手消息，含当时进度、输入文档、预期交付、禁止自动开展的工作；不记录敏感信息。
- 接手确认结果、缺失材料和待处理事项；尚未确认不能标记已就绪。

## 更换或恢复岗位

先读取原岗位记录、最新部门流程与项目进度，再核实旧任务实际状态。保留旧任务 ID、历次消息和结论，登记新任务接替关系；不能覆盖历史冒充原任务始终负责。

将未完成工作、成果版本、阻塞及下一步交给接手者，由其确认后更新当前映射。同岗位避免两个任务同时处理同一工作，旧任务是否终止或归档按实际授权处理。长期保留岗位不代表一直运行；每次接单仍核对当前版本和范围。
