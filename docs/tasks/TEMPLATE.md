# 派工单模板

复制本模板到 `docs/tasks/TASK-YYYYMMDD-NNN.md`。编号、填写与人工校验规则见[部门流程](../workflow.md#派工单与编号)。模板不是已分配任务，不可直接发送；所有占位内容须替换。

## 当前任务

| 字段 | 内容 |
|---|---|
| 任务编号 | TASK-YYYYMMDD-NNN |
| 标题 | 待填写 |
| 创建时间 | YYYY-MM-DD HH:mm:ss +08:00 |
| 下发者 | 项目经理及正式任务 ID |
| 接收岗位 | 一个明确岗位 |
| 接收 Agent ID | 正式任务 ID；草稿阶段可写未确定，不得据此发送 |
| 执行目录 | 接收方实际绝对工作路径 |
| 状态 | 草稿 |
| 父任务／需求编号 | 编号；无则写无并说明 |
| 输入与依据版本 | 文档位置、规格版本、基线完整提交号；未提交另附可复核差异来源 |
| 允许修改 | 具体文件或目录；只读任务写无 |
| 不在范围 | 明确不做的事项和不可修改范围 |
| 依赖 | 前置任务编号及所需状态；无则写无 |
| 交付物 | 文件或报告位置及内容要求 |
| 验收条件 | 可观察且逐项可判断的结果 |
| 验证方法与通过标准 | 命令及预期结果；人工检查则写步骤与判定标准 |
| 预计完成时间 | 时间；无法估算则写原因及下次估算节点 |
| 反馈节点 | 接单、阶段检查及交付时间／事件 |
| 当前阻塞与下一步 | 明确内容；无阻塞写无 |

## 派工历史（只追加）

### D001

- 时间：待填写
- 类型：首次／补充／返工／转派／暂停／恢复
- 下发者与接收 Agent ID：待填写
- 发送前人工校验：待校验；通过时记录校验者及时间
- 发送状态：草稿（通过校验后待发送）

完整发送内容：

```text
填写实际将发送的完整消息，包含任务编号、D001、可访问的任务记录路径、当前版本与任务要求。消息引用的文档必须能在接收方工作目录访问；未提交材料注明来源。
```

发送后追加：发送时间、结果、消息标识（工具未提供时说明）、接单确认及证据。发送失败或结果不确定如实登记，不能提前填已发送／已接单。补充或重试按 D002 等追加，并注明与前次的关系，不改写原消息。

## 执行与交付记录（只追加）

每次反馈记录时间、来源 Agent、对应派工序号与版本、进展／阻塞、成果位置和下一步；待提交反馈时再新增，不预填成功结果。
审核、测试、用户验收及提交／发布分别记录实际结果和证据，不互相代替。
